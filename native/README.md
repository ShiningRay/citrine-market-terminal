# 原生窗口版（native/）

同一棵组件树、同一份业务逻辑，渲染到 **CRuby + libui 原生窗口**（浏览器版见仓库根 README）。

```bash
export PATH="$HOME/.asdf/shims:$PATH"   # libui 只装在 asdf 的 Ruby 3.4.8 上
bin/native                              # 起真窗口（关窗或 Ctrl+C 退出，都走有序拆解）
rake native:test                        # 单测：Memory 桩后端 + Painter::Recording（不开窗口）
rake native:smoke                       # 真窗口冒烟：起窗口 → 买 6 只 → 跑 5 秒收读数 → 自己拆掉
```

依赖：`citrine`（框架）与 `citrine-native`（原生运行时，需已落地自绘面板 area 能力）。
两个仓库默认取同级目录，可用 `CITRINE_ROOT` / `CITRINE_NATIVE_ROOT` 指定。

## 结构：逻辑一行不重写

```
native/
├── app.rb                 # Market::Native::Terminal < Market::Terminal：只覆盖三处平台相关
│                          #   #view（原生视图）· 心跳钩子（Native.every）· #fire_tick 的时钟
│                          #   另加两个挂载钩子：取键盘焦点、设窗口下限（都见下）
├── window_size.rb         # 最小可用窗口：macOS 上给 NSWindow 设 contentMinSize（Fiddle 直通 objc）
├── theme.rb               # 深色主题常量（全部从 app/tokens.rb 派生）
├── views/
│   ├── common.rb          # 面板骨架构件 + 自绘表格几何（Grid/Layout）+ 单元格文本/值域映射
│   ├── chart_data.rb      # 图表 bar 序列（纯函数；与浏览器版 build_bars 逐项一致，有测试锁）
│   ├── header.rb          # 原生控件：品牌/时段/账户总览/运行控制
│   ├── ticket.rb          # 原生控件：下单草稿 + 提交按钮（libui 的 entry 拿不到 Enter）
│   ├── positions.rb       # 原生控件：持仓行（label + 平仓/撤挂单）——**每页 3 行 + 翻页（有界）**
│   ├── debug.rb           # 原生控件：埋点条
│   ├── watchlist.rb       # 自绘：10 行行情（涨跌红绿）+ 点行切标的 + 点表头排序
│   ├── chart.rb           # 自绘：蜡烛/分时 + SMA 折线 + 成交量柱 + 最新价线
│   ├── stats.rb           # 自绘：账户指标 + 权益曲线（polygon 面积 + polyline 折线）
│   └── logs.rb            # 自绘：成交/挂单两张表，挂单表行内可点撤单
└── test/                  # 单测（run.rb 跑全部）+ libui_smoke.rb（真窗口冒烟，默认买 6 只）
```

面板都是"浏览器面板类的子类 + 只重写 `#view`"：props 名字、面板自己的 state
（下单草稿 / 图表取样粒度 / 日志标签页 / **持仓的当前页**）与动作方法全部沿用 `app/views/*`。

## 布局：拉伸式，没有固定像素宽

libui 的 box 只有两件事可声明：`gap`（有没有间距）与 **stretchy**（这个孩子要不要吃掉
剩余空间）。没有 CSS 的 width/height——`area` 的 `size:` 只对**滚动面板**生效、而且只设
"滚动内容尺寸"，不参与布局占位。所以原生侧的组织方式是：

- **三列各 `flex_grow: 1`**（`app.rb`）：libui 把剩余宽度**均分**给 stretchy 的孩子，
  与各自的天然宽度无关。默认窗口（内容 1440×860）下三列各 **461.5**，面板再铺满各自的格子。
- **自绘面板不声明尺寸**：`element(:area)` 走 `Common#paint_panel`（`scroll: false` +
  `flex_grow: 1`），`Draw` 报的就是布局给的真实尺寸，Painter 的 `width/height/clip_rect`
  三者一致。列宽、图表带位、统计两栏都从当次 Painter 的尺寸**按比例算**，
  命中测试用同一份几何（`Grid::Layout`）——窗口一变，画的和点的同时变。
- **文字超宽就截断**（`Common#cell_text` → `fit_text`，省略号）：表格列窄到装不下时，
  画出去的文字会压到下一列（Painter 的 text 不受 `w` 约束），截断比"两列文字叠在一起"好读。
  消融实验（把 `fit_text` 换成原样画、最小窗口截图）：标的列的名会压进最新价列、
  涨跌幅与成交量贴死——所以这个包装不是装饰，是"窄窗口下还看得懂"的前提。
- **列间有呼吸位**（`Grid::CELL_GAP` = 10 / `Grid::NUM_GAP` = 4）：数值列**右对齐**，
  所以"贴到一起"发生在两个相邻的右对齐列之间——左格的数值顶在自己列右缘，右格的数值
  几乎填满自己的列宽时，真实间隙只剩 0.4~2.3px，像素 OCR 直接读成一串
  （`+0.22%1,605.3.`，MARKET-1d 的 P3）。收口方式：
  - 每个右对齐列的**内容框左边**让出 `NUM_GAP`（右缘仍贴列缘，右对齐不变）→
    相邻数值列**最坏情况下**也有 4px 间隙（左对齐的列继续让 `CELL_GAP`）；
  - 第一列不让位（它左边只有面板留白，让出来的 10px 是白扔的）——那 10px 给了最需要
    宽度的「标的」列；
  - 量额列改画收紧后的写法（`Watchlist#compact_unit`）：去掉数字与 `万/亿` 之间的空格、
    万位以上不留小数（`2,388.3 万` → `2,388万`，58.8px → 46.6px）。**单位不能丢**：
    截成 `2,388.3…` 就是差 4 个数量级。图表/下单面板的 label 不窄，照旧用 `Format` 的完整写法。
- **「持」徽标让位**：徽标画在「标的」列右端，名称被截断时会填满整列、压到徽标上
  （真窗口实测重叠 5.3px，OCR 读成 `600519 贵州.持1,392.08`）。现在名称格的可写宽度里
  扣掉徽标宽 + `BADGE_GAP`（4px），实测间隙 5.3~8.9px（最小窗口）/ 15px 以上（默认窗口）。

### 窗口尺寸：默认与最小

| | 尺寸（内容区） | 说明 |
|---|---|---|
| 默认 | **1440×860** | `Terminal::WINDOW`。三列各 **461.5**、四个自绘面板 **461.5×250 / 461.5×282 / 461×332（空账户）/ 461.5×196**；持 1 只 **300**、持 ≥3 只 **164**（持仓列表有界，见下）；**没有任何截断**（截图 + 逐格文字量过六列表头、十行六列数值、统计两栏、图表与两张表的末列） |
| 最小可用 | **1160×790** | `WindowSize::MIN_CONTENT`。三列各 **368**、四个自绘面板 **368×215 / 368×247 / 368×262（空账户）/ 368×126**；持 ≥3 只时走势图 **94**；六列表头齐全、量额都带 `万/亿`、按钮行不叠压（有持仓/成交/挂单时逐项量过） |

**持仓列表是有界的（MARKET-1d 的 P1）**：持仓行是原生控件，一行实测 **64px**；libui 的 box
**先把天然高度分给非 stretchy 的孩子**，剩下的才给 stretchy 的——所以持仓行数一旦随持仓增长，
中列的走势图就被吃光。修复前真窗口实测（默认窗口 1440×860，逐只买入）：

| 持仓只数 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 8 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| 走势图高 | 340 | 300 | 236 | 172 | 108 | 44 | **0** | **0** | **0** |
| 窗口内容高 | 860 | 860 | 860 | 860 | 860 | 860 | 880 | 1008 | 1136 |

（1160 宽下更早：0/1/2/3/4 只 → 270/230/166/102/38，**5 只起 0×0**。注意窗口被内容顶高也
救不回来——走势图自己的天然高度是 0。）

修法：**每页 `PAGE_SIZE`（=3）行 + 翻页**（`native/views/positions.rb`）。持仓面板的天然高度被
钉在 ~4 行（≈256px），走势图必然拿得到剩余高度；每只持仓的「平仓/撤挂单」仍然点得到（可能在
第 2、3 页）。修复后同一阶梯（默认窗口）：

| 持仓只数 | 0 | 1 | 3 | 6 | 10 | 12¹ | 20¹ |
|---|---|---|---|---|---|---|---|
| 走势图高 | 332 | 292 | **164** | **164** | **164** | **164** | **164** |
| 窗口内容高 | 860 | 860 | 860 | 860 | 860 | 860 | 860 |

¹ 目录里只有 10 只标的，12/20 只用的是一份"合成持仓"探针（只为压布局，不做交易），
证明"再多也不会变"；行数有界的守卫在 `native/test/positions_paging_test.rb`（真渲染行数 ≤
`PAGE_SIZE`）与 `native/test/layout_test.rb`（高度预算 +150px），真窗口守卫在 `libui_smoke.rb`
（**冒烟默认就买 6 只**，并断言走势图 ≥150px；把分页去掉，冒烟立刻红——见"反例"一节）。
1160 宽下同一份代码：持 0 只 262、持 ≥3 只 **94**（都不为 0，K 线/量柱/刻度都在）。

最小尺寸由 `native/window_size.rb` 在挂载时设为窗口的内容区下限（macOS：
`[NSWindow setContentMinSize:]`，Fiddle 直通 libobjc；取 NSWindow 的办法是
`LibUI.control_handle(uiWindow*)`——**不要**直接给 `uiWindow*` 发 objc 消息，那是 libui 的
结构体指针，会段错误）。设完 `minSize` 会被 AppKit 同步成 **1160×822**（含标题栏），
用户拖不出更小的窗口。平台不支持时该函数如实返回 `false`（不假装设上了），
此时只剩 libui 自己的**内容自然尺寸下限**兜底。

> **这个下限只约束交互式缩放**（如实说明，`WindowSize.warn_scope` 在 dev_mode 下也会打这条）：
> AppKit 由 `contentMinSize` 推出 `minSize`，用户拖拽走的是它；**程序化 `setContentSize` /
> `setFrame` 不经过它**。实测（本轮复验）：
>
> | 请求（内容尺寸） | 空账户落点 | 持 10 只落点 |
> |---|---|---|
> | 1160×790（声明下限） | 1160×790 | 1160×790 |
> | 900×600（远低于下限） | **1046×664** | **1084×696** |
>
> 落点是 **libui 自己的内容天然下限**（低于它 OS 也不让缩），那个尺寸下
> 「成交与挂单」面板会先被挤成 0 高（框架的 dev_mode 报 `拿到了 0 尺寸`）。
> 修持仓分页之前，持 6 只就能把天然下限顶到 **1136×880**（**高于** 1160×790 的声明，
> 于是"应用的下限压得住框架的下限"只在空账户成立）；现在持仓再多也只有 ~1084×696，
> 声明的 1160×790 在数据状态下**真的**压得住了。

### Windows 平台（2026-09-15 实测，Ruby 4.0.6 x64-mingw-ucrt + libui 0.2.4）

- **原生控件更高**（label 17px / button 25px；0 持仓基线 290 vs macOS 实测 340），
  上面的面板尺寸表是 macOS 数字，Windows 实测（持 6 只、默认 1440×860）：
  自选 235 / 统计 269 / **走势 217** / 成交挂单 139。
- **走势图文字并入自绘面板**：三段行情文字（quote_head / quote_stats / tech_stats）原先
  是原生 label，合计 ~119px 自然高度，Windows 上把走势图压到 71px（画不出蜡烛）；
  现改为 `Painter.text` 画在面板顶部/底部带（`chart.rb` 的 HEAD_BAND / STATS_BAND），
  "原生 label 不换行会顶高中列最小宽度"的拆行约束随之消失，两个平台同时受益。
  本机（Windows）冒烟已过；macOS 侧同一份代码待下次在 macOS 上复跑冒烟确认。
- **stretchy 链在 Windows 是严格的**：根元素与每层"参与拉伸的 box"都必须自己声明
  `flex_grow: 1`（macOS 对窗口直系子元素宽容，Windows 断一处、里面的 area 就塌成 0×0
  且 Draw 一次都不触发）。本轮补了根 box 与三列所在 row 的声明。
- 最小尺寸下限（`WindowSize`）在 Windows 不可用（macOS 专属的 `setContentMinSize:`），
  `enforce` 如实返回 `false`，只剩 libui 的内容自然尺寸兜底——与上文口径一致。
- 退出路径的信号注册按 `Signal.list` 过滤：Windows 没有 HUP/QUIT/ALRM（trap 直接
  ArgumentError），只剩 INT/TERM。

**键盘焦点**：原生没有 window 级 keydown，`window_key` 声明的全局快捷键由**收到按键的那个
area** 转发（设计文档 2.3）。挂载时应用会自己把焦点拿到自选面板上（`Market::Native::Terminal
#focus_keyboard_target`：`Widgets#window_activate` 激活应用 + `AreaHandle#focus` 聚焦）；
平台给不了焦点时（非 macOS）**先点一下任意自绘面板**即可。

## 退出路径：先退出主循环，再拆解（MARKET-1d）

`Citrine::Native.run` 把 `teardown` 放在 `ensure` 里，但 Ruby 对**未捕获的终止信号**是直接
终止进程、不跑 `ensure`——libui 的窗口/控件被系统回收，框架那套"谁创建谁销毁"的记账
（`dispose` → `uiControlDestroy`）完全没走。反过来，信号若恰好落在 Ruby 代码段（例如 200ms
一次的心跳回调里），Ruby 会开始展开栈并跑 `teardown`，此时**在强杀下执行 libui 的析构是不
安全的**（MARKET-2b §9 F5 记录的 `dispose → box_delete` 段错误）。

所以 `bin/native` 把可捕获的终止信号统一接到"`quit` 主循环 → `run` 的 `ensure` 里有序拆解"。
信号注册现在由框架提供（E3 落地后）：

```ruby
app = Citrine::Native.start(...)
app.trap_quit!   # 按 Signal.list 过滤平台实际存在的信号（Windows 没有 HUP/QUIT/ALRM）
app.widgets.main_loop
app.teardown
```

`trap_quit!` 返回**真正装上**的信号名（便于记日志/断言）；把应用当独立进程跑的脚本也可以
一步到位：`Citrine::Native.run(MyApp, signals: :default)`。**默认不接管**——`trap` 是进程级的，
会覆盖宿主已有的处理器，所以库不主动装（有判别用例锁住这条）。

`uiQuit` 本身线程安全，`trap` 在主线程的安全点执行，而主循环里 200ms 一次的心跳回调就是
那个安全点——所以 Ctrl+C 之后最多 200ms 就走完主循环。实测（每项 3 次，`/tmp/m1d/probe_exit.rb`）：

| 信号 | 修复前 | 现在 |
|---|---|---|
| `SIGINT`（Ctrl+C） | 进程被信号带走（exit=nil, termsig=2），拆解没跑 | **exit=0**（有序拆解） |
| `SIGTERM`（`kill`） | 同上（termsig=15） | **exit=0** |
| `SIGALRM` | 同上（termsig=14，复审记过 3 次里 2 次段错误） | **exit=0** |
| `SIGKILL` | exit=nil（不可捕获） | exit=nil（**唯一一条绕过拆解的路径**：进程直接消失，不会踩析构） |

> 边界如实写明：**只有不可捕获的 `SIGKILL` 会跳过拆解**。本轮 9 次信号实验（INT/TERM/ALRM
> 各 3 次）全部 `exit=0`、日志无 `[BUG]`；`SIGKILL` 3/3 干净地消失。若将来有人在
> `bin/native` 之外启动应用（例如自己 `Citrine::Native.run` 而没传 `signals:`），
> 这条保护就没有了——所以框架里的默认是"不接管信号"，要这条保护必须显式要求。

## 反例与消融实验（MARKET-1d）

全部在 `/tmp/m1d/repo-copy`（**被审仓库零改动**）里做，改完即还原。结论：本轮新增的守卫
**都会红**，所以它们不是花架子。

| 人为破坏 | 红在哪 |
|---|---|
| 把 `Positions::PAGE_SIZE` 改成 99（= 去掉分页上界） | `native:test` 6 条红（分页 5 条 + 高度预算）；`native:smoke` 复现原缺陷：`chart [0.0, 0.0]`，并打出 `持 6 只时走势图只有 0.0px 高（应 ≥150）` |
| 去掉徽标让位（`reserve:`） | `test_held_badge_reserves_room_in_the_name_cell` 红（名称右缘 89.8 > 徽标 x=88.6） |
| `volume_cell/amount_cell` 退回 `Format` 原样 | `test_volume_and_amount_cells_keep_their_unit` 红（第 0 行就丢单位：`134.6…`、`18.61…`） |
| `Grid::NUM_GAP` 改成 0 | `test_adjacent_numeric_columns_cannot_touch` 红（最坏情况间隙 0.0px） |
| 列权重退回 MARKET-1c 那组（122/66/66/64/70/70） | `test_numeric_columns_fit_the_widest_real_cell_at_the_minimum_window` 红（「涨跌幅」内容宽 46.3 < 表头 `涨跌幅 ▼` 的 48.34px） |

**保留的包装，各自挡住了什么**（消融后仍能通过验收的都删掉了）：

| 包装 | 挡住什么 / 为什么留 |
|---|---|
| 持仓分页（`PAGE_SIZE` + 翻页 + 页码钳制） | 走势图被持仓吃光（上面第一行反例）——**核心修复**，不是可选包装 |
| `reserve: { 0 => 徽标宽 + BADGE_GAP }` | 徽标与截断名称重叠（OCR `600519 贵州.持1,392.08`） |
| `compact_unit` | 量额丢单位（差 4 个数量级） |
| `Grid::NUM_GAP` + 第一列不让位 | 相邻数值列被 OCR 读成一串；第一列那 10px 白扔的留白给了最需要的「标的」列 |
| 冒烟的 6 只持仓场景 + `CHART_MIN_HEIGHT` | 空账户跑 4 秒**看不见**这条缺陷（复审就是这么反证的）；`≥150` 的阈值只由真窗口给得出 |
| `layout_test.rb` 的高度预算（620/192/64/64） | 没有窗口时也能挡住"把 PAGE_SIZE 调大 / 给中列加 chrome"（模型与真窗口实测逐点对齐：持 1 只 292、持 3 只 164） |
| `bin/native` 的信号 trap | 强杀落在 Ruby 段时 `teardown` 半途拆控件（段错误）；现在 9/9 `exit=0` |

## 已知取舍（原生侧）

- **三列必然等宽**：libui 的 stretchy 是**布尔**，同层 stretchy 兄弟**等分**，没有权重 /
  最小宽度可用。所以"右列窄一些"（下单面板天然只要 ~395）在原生侧做不到——除非给右列塞
  一个更宽的天然控件当尺子，那更糟。代价是右列偏空、中列没能多拿宽度；收益是左列不再塌
  （三列 368/461.5/714.5 随窗口线性缩放，无信息损失），MARKET-2b 复审判为可接受。
- **最小窗口下持仓行的名称截得更狠**：1160 宽时「标的」列内容宽 ~97px，而"600519 贵州茅台"
  要 94.4px、再加上「持」徽标要让出 ~15px——所以**带徽标的行**只剩 1~2 个汉字
  （`600519 贵州…` / `002594 比…`），无徽标的行名称完整。取舍是"徽标让位、绝不重叠"
  优先于"名称多显示一个字"（代码 6 位始终完整，完整名称在走势图标题与下单面板里）。
- **布局全是拉伸式的，没有固定像素宽**：三列靠 `flex_grow` 均分宽度、面板铺满自己的格子、
  绘制几何从 Painter 的尺寸按比例算（见上）。所以窗口大小一变，列宽/图表/表格跟着变，
  窄到一定程度文字截断（省略号）而不是溢出。
- **哪些面板给 `flex_grow` 是有讲究的**（真窗口量出来的 libui 规则）：
  - 含自绘 area 的面板（自选/统计/走势/成交挂单）**必须** stretchy：面板框与 area 的天然
    尺寸都是 0，不给自己要空间就永远收不到 Draw；
  - 纯原生控件的面板（`下单` / `持仓`）**不能** stretchy：libui 的 box 最小高度 ≈
    stretchy 孩子数 ×（其中最大的天然高度）+ 间距，把下单面板也算进去会让窗口最小高度
    直接翻倍（实测：全部 stretchy 时内容下限 1264×936，窗口几乎缩不动）。
- **不要留空的嵌套 box**：libui 会把整列的剩余空间分给空容器（实测：下单面板里"限价输入"
  那个容器在市价模式下是空的，它长到 212px，把下面的成交/挂单表挤成 0 高）。所以条件内容
  要么保证容器里始终有东西（现在市价模式下留一行说明 label），要么把元素直接放在父容器里。
  `native/test/layout_test.rb` 有一条"树里没有空 box"的回归守卫。
- **长 label 会把窗口顶宽**：原生 label 不换行，它的天然宽度是所在列（进而整窗）的宽度下限。
  顶部快捷键说明、走势图的报价/指标行、下单面板的报价/预估行因此都拆成了多行
  （单行时窗口最小宽度 ~1400，小窗口根本用不了）。
- **面板没有滚动条**（`scroll: false`）：内容按面板宽度重新排布，不靠横向/纵向滚动看数据。
- **没有鼠标悬停高亮**（`on_mouse_move` 可用但本版未接）；图表不支持拖拽缩放。
- 输入框没有 placeholder，说明文字写在相邻 label 里。
